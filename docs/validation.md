# 검증 범위와 한계

이 문서는 재현 가능한 검증 방법과 지원 범위를 설명한다. 개인 대화·승인 원문·실행별 로그·계정 정보는 배포하지 않는다.

## 환경과 명령

검증 환경은 Linux x86_64, Python 3.12 계열이다. Gitleaks 검증 기준은 v8.30.1이다. 실제 모델 연동에는 해당 CLI·인증·모델 접근과 bubblewrap 실행이 가능한 환경이 별도로 필요하다.

프로젝트 루트에서 다음 명령을 실행한다.

전체 회귀나 OS 격리 검사를 실행할 프로젝트 사본은 실제 경로가 `/tmp`·`/var/tmp` 밖에 있도록 둔다. 읽기 격리 검사는 프로젝트 내부에 시험용 의존 파일을 만들며, 검증기는 전용 임시 공간과의 충돌을 막기 위해 이 두 경로 아래의 런타임·의존 파일을 거부한다. 따라서 사본을 이 경로에 두면 namespace 생성이 가능한 환경에서도 해당 검사가 경로 오류로 실패할 수 있다. 이는 아래의 환경 제한에 따른 skip과 구분한다.

```sh
python3 -B -m unittest discover -s modules/tests -p 'test_*.py' -v
bash modules/tests/test_save_dialog.sh
```

회귀 205개에는 보안 hook 검사 22개가 포함된다. 저장기 18개는 별도다. 합성 입력과 모의 에이전트를 사용하며 실제 모델 호출은 하지 않는다. Gitleaks가 없으면 실제 scanner 통합 시험이 skip되고, 호스트가 namespace 생성을 제한하면 OS 격리 시험이 skip될 수 있다. skip은 통과로 계산하지 않는다.

OS 격리 검사 2개만 확인하려면 위 경로 조건과 bubblewrap의 namespace 생성이 허용되는 실행 환경을 준비한 뒤 다음 명령을 실행한다. 완료 기준은 두 검사 모두 skip 없이 통과하는 것이다.

```sh
python3 -B -m unittest modules.tests.test_m5.SandboxTests -v
```

## 확인 범위

| 영역 | 검사 내용 |
|---|---|
| 입력·승인 | 원문 출처·해시·허용 범위·신원·기록 책임 결속 |
| 실행·반복 | 실제 subprocess, 구현·검증·리뷰 순서, 오류 전파·시간 및 라운드 한도 |
| 격리 | 작업 공간 읽기 전용, 호스트 비밀 파일·네트워크 접근 제한, 명시된 런타임만 노출 |
| 기록·복구 | 저장 중복·충돌·동시성·손상 처리, caller 연결, 중단·저장 전용 복구 |
| 운영 조회 | 정적 사전 점검·보고·증거 종류 분류·백그라운드 시작과 중단 |
| Git 보안 | 정상 커밋·합성 토큰 차단, 최초·부분 스테이징·별도 인덱스, 도구 오류, 설치 충돌·반복 설치 |
| 설치 경로 | 공백 포함 경로·폴더명 변경·로컬 clone, 파일 바이트·실행 비트·LF 보존 |

## 공개 파일 사본의 검증 결과

공유 대상만 복사한 공백 포함 경로의 임시 저장소에서 다음을 확인했다. 내부 개발 문서와 실제 기록 없이 동작하는지 점검했으며, 실제 모델은 호출하지 않았다.

| 검사 | 결과 |
|---|---|
| 최초 회귀 | 205개 실행, 203개 통과·OS 격리 2개 skip |
| 별도 OS 격리 검사 | 동일 소스의 공개 사본에서 2개 통과, skip·실패·오류 0개 |
| 저장기 | 18개 통과 |
| 리뷰 준비 | 내부 문서가 없는 사본에서도 성공. 내부 문서에 합성 비공개 표식을 추가한 경우에도 공개 가이드만 복사하며 해당 표식은 포함하지 않음 |
| 기록 제외 | `approvals/`, `dialog/`, `runs/`는 초기 공유 사본에 빈 `.gitkeep`만 존재 |
| Git 검사 | 후보 디렉터리·비어 있지 않은 스테이징·임시 커밋 이력의 Gitleaks 검사 통과 |
| 기본 명령 | 정책 기본값 조회·preflight 도움말 정상 |

최초 회귀의 OS 격리 2개는 호출 환경에서 bubblewrap의 namespace 관련 `NETLINK_ROUTE` 소켓 생성이 거부되어 skip됐다. 이후 `/tmp`·`/var/tmp` 밖에 공유 파일만 복사하고 namespace 생성이 허용되는 환경에서 두 검사를 별도로 실행해 모두 통과했다. 보호 파일 쓰기·호스트 네트워크 접근 차단과 호스트 비밀 파일 읽기 차단·명시된 의존 파일 접근을 확인했다. 실행 전후 원본과 사본의 공유 파일 해시·권한이 같았으며 코드나 격리 정책은 변경하지 않았다.

기존 203개와 별도 격리 2개의 결과를 합쳐 동일 소스의 205개 항목에 대한 통과 근거를 확보했다. 최초 skip을 통과로 바꿔 계산하거나 전체 205개가 한 번의 실행에서 통과했다고 표시하지 않는다. 이번 경로 안내·결과 문서 보완에 대한 별도 모델의 독립 리뷰는 수행하지 않았다. 이후 소스·설정 변경에는 필요한 검증을 다시 수행한다.

## 결과를 해석하는 기준

- `preflight ready`는 정적 조건 확인이다. 실제 로그인·모델 가용성·네트워크·sandbox 성공을 보장하지 않는다.
- `report_status: ok`는 조회 성공이며 작업 성공과 다르다. `execution.status`, `dialog.recording_status`, 무결성 결과를 따로 확인한다.
- 시험 통과와 교차 리뷰는 같은 코드 상태에 대한 근거여야 한다. 이후 문서·코드를 수정한 것을 과거 리뷰가 승인했다고 표시하지 않는다.
- 로컬 경로 이동 검증은 다른 PC나 Windows·macOS 실행 검증을 대신하지 않는다.
- 6시간 모델 호출·24시간 연속 운용·인증 갱신은 검증 완료 범위가 아니다. 장시간 독립 테스트 실행과 장시간 모델 세션을 구분한다.
- Gitleaks 통과는 실제 대화·계정 상태 등 모든 사적 정보가 없다는 뜻이 아니다. 문서·바이너리·압축 내부의 탐지 한계는 [공유 안내](sharing.md)를 따른다.

실제 모델 시험과 백그라운드 관리 절차는 [운영 가이드](usage.md)에 있다. 합성 시험의 통과를 실제 서비스 호출 결과로 보고하지 않는다.
